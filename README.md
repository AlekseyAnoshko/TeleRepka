# TeleRepka — Repka Pi Lab Hub

Информационная панель лаборатории на одноплатном компьютере **Repka Pi 4**. Миникомпьютер подключается к телевизору по HDMI, работает в режиме киоска и собирает в одном локальном веб-сервисе всё, что нужно сотрудникам в общем помещении: показания датчиков, расписание сотрудников, трансляцию экрана с рабочих мест и удалённое управление телевизором.

Сервис написан на Flask и Socket.IO, не использует облачных сервисов-посредников и не требует подписки. Часть функций зависит от внешних источников (подробности в разделе «Зависимость от внешней сети»).

## Возможности

| Функция | Что делает | Где реализовано |
|---|---|---|
| Датчики | Температура, относительная влажность и атмосферное давление (BME280), CO₂ (MH-Z19B); обновление каждые 5 секунд | `sensors.py`, `app.py` |
| Расписание сотрудников | Справочник сотрудников лаборатории и расписание занятий выбранного преподавателя; выбор синхронизируется с ТВ | `employees.py`, `laboratory_sync.py`, `schedule_parser.py` |
| Трансляция с рабочих мест | Сотрудник открывает `/broadcast` и выводит экран либо камеру и звук на ТВ через WebRTC без установки ПО | `templates/broadcast.html`, `templates/index.html` |
| Управление ТВ из браузера | Предпросмотр экрана ТВ, мышь, клавиатура, быстрые кнопки RuTube, YouTube, Яндекс.Музыки, возврат к панели | `app.py` (CDP, X11) |
| Фоторамки ESP32 | Статус устройств ESP32 PhotoFrame и доступ к их веб-интерфейсам через прокси | `photoframes.py` |

## Как это работает

```text
Рабочее место сотрудника (браузер)
        │  HTTPS + WebSocket
        ▼
   nginx (TLS, внешний доступ)  ──►  Flask + Flask-SocketIO (app.py, 127.0.0.1:5000)
                                      ├─ sensors.py      BME280 (I²C1) и MH-Z19B (UART)
                                      ├─ photoframes.py  опрос и прокси ESP32 PhotoFrame
                                      ├─ employees.py    SQLite + schedule_parser.py
                                      └─ WebRTC-сигнализация, управление ТВ

Repka Pi 4
  ├─ GDM-сеанс «TeleRepka Kiosk» ──► Chromium (CDP 127.0.0.1:9222) ──► HDMI ──► ТВ
  └─ Wi-Fi хотспот 10.42.0.0/24  ◄──► ESP32 PhotoFrame
```

Flask слушает только `127.0.0.1:5000`; доступ с рабочих мест, HTTPS и WebSocket проксирует nginx. Видео и звук трансляций идут от рабочего места на ТВ напрямую по WebRTC, сервер выполняет только сигнализацию. Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Требования

**Оборудование:** Repka Pi 4; телевизор или монитор с HDMI (в проверенной конфигурации 3840×2160); модуль BME280 (I²C); датчик CO₂ MH-Z19B (UART); по желанию фоторамки ESP32 PhotoFrame.

**Программное обеспечение:** Repka OS 4 «Базовая» (последняя версия этой редакции основана на Ubuntu 22.04.5), aarch64, ядро 6.12.x (на проверенной плате 6.12.9.7-repka-pi4), менеджер входа GDM, Python 3 с виртуальным окружением, Chromium из Snap, `xdotool`, `wmctrl`, `x11-xserver-utils`, `curl`; nginx для HTTPS и внешнего доступа.

> Редакция Repka OS 4 «Образование» (v2.0.0) основана на Ubuntu 25.10 и поддерживает Wayland. Проект на ней не проверялся: сеанс киоска, `xdotool` и управление мышью рассчитаны на X11.

## Установка на новую плату

Установщик предназначен для **чистой** Repka Pi. Не запускайте его на действующей плате.

```bash
sudo apt-get update && sudo apt-get install -y git
mkdir -p ~/git && git clone https://github.com/AlekseyAnoshko/TeleRepka.git ~/git/TeleRepka
cd ~/git/TeleRepka

sudo bash deploy/install.sh --user <пользователь> --with-kiosk --dry-run   # только показать план
sudo bash deploy/install.sh --user <пользователь> --with-kiosk
sudo bash deploy/check.sh
sudo reboot
```

Флаг `--with-kiosk` включает автологин GDM и полноэкранный Chromium; без него устанавливается только сервер. Установщик создаёт виртуальное окружение, службу `lab-hub-kiosk.service` (запускает только Flask) и файл с секретом `/etc/telerepka/lab-hub.env` (права 0600). nginx, squid и nftables установщик не настраивает. Подробности и ограничения: [deploy/README.md](deploy/README.md), [kiosk/KIOSK.md](kiosk/KIOSK.md).

### Запуск для разработки

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python app.py        # http://127.0.0.1:5000
```

Без платы сервис запускается: датчики возвращают `None` (на панели прочерки), функции управления ТВ вернут ошибку, пока нет Chromium с включённым CDP. Правила работы с проектом: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Конфигурация

`config.json`:

```json
{
  "sensor_poll_interval_sec": 5,
  "photoframe_poll_interval_sec": 30,
  "photoframes": [
    { "name": "Фоторамка Иванова", "ip": "10.42.0.101" }
  ]

```

Секрет приложения задаётся переменной окружения `LAB_HUB_SECRET` (значение по умолчанию `change-me` в рабочей установке использовать нельзя).

## Датчики

На основной плате проверены **BME280** и **MH-Z19B** (26.10.2026): BME280 показал около 23,0 °C, 18 % и 732 мм рт. ст., MH-Z19B — 640–702 ppm. Все четыре значения отображаются в панели «ДАТЧИКИ» на веб-странице и на ТВ.

| Датчик | Измеряет | Интерфейс | Параметры |
|---|---|---|---|
| BME280 | температура, влажность, давление | I²C1, `/dev/i2c-1` | адрес `0x76`, chip ID `0x60` |
| MH-Z19B | CO₂, ppm | S-UART, `/dev/ttyS2` | 9600 бод, таймаут ответа 2 с |

Подключение BME280:

| Вывод модуля | Контакт 40-pin | Примечание |
|---|---:|---|
| VCC | 1 | 3,3 В, не 5 В |
| SDA | 3 | PA12, I²C1 SDA |
| SCL | 5 | PA11, I²C1 SCL |
| GND | любой GND | общая земля |

Контакты CS и ADDR/MISO шестивыводного модуля, а также TX, RX, VCC и GND датчика MH-Z19B в проверках не фиксировались. Перед переподключением сверяйтесь с реальным монтажом, а не с предполагаемой распиновкой.

Настройка интерфейсов в `/boot/repkaEnv.txt`:

```ini
overlays=w1_gpio i2c3 s_uart i2c1
```

После этого должны существовать `/dev/i2c-1` и `/dev/ttyS2`. Шину `/dev/i2c-6` не сканировать: она связана с HDMI.

- Давление показывается фактическое, на высоте датчика, без приведения к уровню моря: `мм рт. ст. = гПа × 0,750061683`.
- Опрос выполняется одним циклом: `sensors.read_all()` возвращает температуру, влажность, CO₂ и давление, `app.py` отправляет событие Socket.IO `sensor_data` и ждёт `sensor_poll_interval_sec` (5 с) после работы датчиков.
- Проверка без веб-сервиса: `.venv/bin/python sensors.py`.

**DHT11 и MQ-135 в проекте не используются.** `read_dht11()` возвращает пустые значения. В корне репозитория остаются отладочные скрипты прежних экспериментов (`dht_debug*.py`, `sensors5.py`, `sensors_gpiod_test.py`); `app.py` использует только `sensors.py`.

**Планируется:** уличный датчик DS18B20 на ESP32 (30 pin, Wi-Fi) в сети хотспота. Опрос по HTTP REST аналогично `photoframes.py`, без MQTT-брокера и LoRaWAN-шлюза.

## Фоторамки ESP32

Рамки подключаются к Wi-Fi хотспоту Repka Pi. `photoframes.py` раз в `photoframe_poll_interval_sec` секунд опрашивает их REST API, статус отображается на панели. Веб-интерфейс каждой рамки доступен через прокси `/photoframe/<имя>/`. Для слайдшоу служит маршрут `/slideshow.jpg`: он по кругу отдаёт изображения (`.jpg`, `.jpeg`, `.png`, `.bmp`) из каталога `pic_aaf/`. Описание самих рамок находится в репозитории esp32-photoframe (`docs/REPKA_PI_PHOTOFRAME.md`).

## Трансляция с рабочих мест

1. Сотрудник открывает `/broadcast` по адресу сервиса (HTTPS обязателен).
2. Вводит имя и нажимает «Показать экран на HDMI» или «Показать камеру + звук на HDMI».
3. Трансляция появляется на ТВ плиткой, при активной трансляции панель разворачивается на весь экран; несколько сотрудников могут транслировать одновременно.

**Почему нужен HTTPS.** Браузерные `getDisplayMedia()` и `getUserMedia()` работают только в защищённом контексте (HTTPS либо `localhost`). Поэтому внешний доступ к `/broadcast` обеспечивает nginx с сертификатом (пример: `nginx_telerepka.conf`). При самоподписанном сертификате браузер один раз покажет предупреждение.

**Сигнализация и ICE.** Обмен `broadcaster-offer`, `tv-answer`, `ice-candidate`, `broadcaster-stop` идёт через Socket.IO. В обеих страницах указан STUN `stun.l.google.com`; TURN-сервер не настроен, поэтому при симметричном NAT у отдельных рабочих мест установить соединение может не получиться.

## Управление ТВ

Сотрудник открывает панель на своём компьютере и управляет ТВ без клавиатуры и мыши:

- **Предпросмотр экрана ТВ** — Chrome DevTools Protocol (`Page.startScreencast`): не чаще двух JPEG-кадров в секунду, до 1600×900, качество 65.
- **Мышь** — `xdotool` в сеансе X11, координаты пересчитываются в 3840×2160 (`/tv/input/mouse`).
- **Клавиатура и медиаклавиши** — события CDP (`/tv/input/key`, `/tv/media`).
- **Быстрые кнопки** — RuTube, YouTube, Яндекс.Музыка. Допустимы только адреса из белого списка (`rutube.ru`, `www.youtube.com`, `music.yandex.ru`).
- **«Вернуть панель на ТВ»** — `/tv/go-home`; `/tv/open-meetings` открывает сервис протоколов совещаний.

Порт CDP `9222` слушает только `127.0.0.1` и **не должен** быть доступен из сети. Служебное окно «Дисплей» (`xfce4-display-settings`), которое появляется при включении и выключении ТВ, закрывается автоматически.

## Расписание сотрудников

Кнопка «Расписание сотрудников» открывает список сотрудников лаборатории с поиском. Выбор сотрудника показывает его расписание занятий и синхронизируется с ТВ через Socket.IO. Во время активной трансляции приоритет остаётся у трансляции.

- Справочник формируется из [страницы сотрудников ИРНИТУ](https://www.istu.edu/struktura/setevykh_tekhnologiy/sotrudniki) и может дополняться локальными записями.
- Данные хранятся в локальной SQLite-базе `data/laboratory_employees.db`; в Git она не попадает (`.gitignore`). При первом запуске `employees.init_db()` создаёт таблицу `employees`.
- Первичное заполнение и обновление: `.venv/bin/python laboratory_sync.py` (просмотр) и `.venv/bin/python laboratory_sync.py --apply` (запись).
- API: `/api/employees`, `/api/employees/<id>/schedule`.
- У части сотрудников расписание не привязано. Синхронизация справочника привязки не создаёт.

## Киоск, GPU и декодирование видео

ТВ показывает `http://localhost:5000/?kiosk=1` в Chromium, который запускает GDM-сеанс «TeleRepka Kiosk» (`kiosk/`). Панель масштабируется CSS на 150 %, Chromium работает с масштабом 100 % на текущем разрешении X11. Сеанс при сбое браузера перезапускает его через 3 секунды.

**Результаты проверки на основной плате (26.10.2026):**

- Графика ускорена: Mali-T720 через Panfrost и ANGLE (OpenGL ES 2.0), `gpu_compositing` и растеризация включены. Параметры запуска: `--use-gl=angle --use-angle=gles-egl --ignore-gpu-blocklist --enable-gpu-rasterization`.
- **Аппаратного декодирования видео в Chromium нет** (`video_decode: disabled_software`). Основная нагрузка на CPU — зацикленная заставка `static/video_lns.mp4` (1280×720, 24 к/с, около 5 Мбит/с): процесс `chrome` занимал около 84 % CPU, а после паузы заставки — около 4 %.
- Аппаратный декодер Allwinner H6 (Cedrus) исправен и доступен в GStreamer: 8-секундный ролик 720p H.264 декодируется элементом `v4l2slh264dec` за 0,53 с процессорного времени против 11,17 с у программного декодера.
- Snap-сборка Chromium Cedrus не использует. Драйвер VA-API `libva-v4l2_request` не подходит: он требует многоплоскостный интерфейс `V4L2_CAP_VIDEO_M2M_MPLANE`, а Cedrus его не предоставляет. WebKitGTK 2.50.4 из Ubuntu воспроизводит H.264 через Cedrus без потерянных кадров, но в этой сборке нет WebRTC (`RTCPeerConnection` не определён).

Практические рекомендации: использовать облегчённую заставку (например, 960 пикселей по ширине, 15 к/с, H.264 baseline) и ограничивать разрешение и битрейт трансляций.

> Не изменяйте параметры GPU, GDM, X11, разрешение 4K и масштаб панели без отдельной проверки: подробности в [kiosk/KIOSK.md](kiosk/KIOSK.md).

## Сеть

- Repka Pi подключена к сети университета по проводному Ethernet и раздаёт Wi-Fi как хотспот `TeleRepka` (профиль NetworkManager `TeleRepka-Hotspot`, интерфейс `wlan0`, адрес `10.42.0.1/24`, DHCP, DNS и NAT через режим `shared`).
- Скрипт восстановления: `network/setup-hotspot.sh`; он пересоздаёт профиль, и подключённые клиенты могут временно потерять связь. Пароль передаётся только через переменную `HOTSPOT_PASSWORD` и в репозитории не хранится.
- Конфигурации `nginx_telerepka.conf`, `squid.conf` и `nftables-photoframe-proxy.conf` — примеры для внешнего доступа и фоторамок. Фактически применённые настройки проверяйте на устройстве.

## Зависимость от внешней сети

Сам сервис работает в локальной сети, но отдельные функции требуют внешнего доступа:

| Функция | Что нужно |
|---|---|
| Синхронизация сотрудников, расписание | доступ к `www.istu.edu` |
| RuTube, YouTube, Яндекс.Музыка | интернет |
| STUN для WebRTC | доступ к `stun.l.google.com` (в локальной сети обычно не критичен) |
| Датчики, фоторамки, трансляция в одной сети | внешний доступ не нужен |

## Эксплуатация

```bash
cd ~/git/TeleRepka
git -c core.pager=cat status --short --branch
SYSTEMD_PAGER=cat systemctl is-active lab-hub-kiosk.service
curl -sS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:5000/
curl -fsS http://127.0.0.1:5000/api/employees | head -c 300
sudo bash deploy/check.sh
```

- Перезапуск Flask: `sudo systemctl restart lab-hub-kiosk.service`. GDM и Chromium перезапускать не нужно, но WebSocket-соединения кратковременно оборвутся. После правки `templates/index.html` или `app.py` перезапуск нужен, затем обновите страницу (`Ctrl+Shift+R`) и страницу на ТВ.
- Лог сеанса киоска: `~/telerepka-session.log`; сервер: `journalctl -u lab-hub-kiosk.service`.
- Резервная копия базы сотрудников: остановите службу и скопируйте `data/laboratory_employees.db` (при режиме WAL — согласованным снимком, а не копированием работающего файла).
- Перед обновлением проверьте локальные изменения и сделайте резервную копию. В блоках для интерактивной SSH-оболочки не используйте `exit`, для `systemctl` указывайте `--no-pager`.
- Графическая сессия отличается от SSH: команды `xrandr` и `xdotool` из SSH требуют `DISPLAY=:0` и корректного `XAUTHORITY`.

## Безопасность

Сервис рассчитан на изолированную сеть лаборатории и **не готов к публикации в интернете**:

- нет аутентификации для `/broadcast`, управления ТВ и API;
- Socket.IO принимает подключения с любого источника (`cors_allowed_origins="*"`);
- сервис запускается от root (исторически из-за GPIO SysFS для DHT11); возможность запуска от обычного пользователя после перехода на I²C и UART ещё не проверена;
- секрет по умолчанию `change-me`;
- порт CDP `9222` открывает полное управление браузером и должен оставаться на loopback.

Минимальные меры: задать `LAB_HUB_SECRET`, ограничить доступ на уровне nginx и межсетевого экрана, не публиковать сервис вне сети университета.

## Известные ограничения и планы

- Нет истории показаний датчиков и оповещений по порогам (например, CO₂).
- Уличный датчик DS18B20 на ESP32 пока не реализован.
- Разрешение 3840×2160 жёстко задано в пересчёте координат мыши; фото сотрудников перечислены в `templates/index.html`.
- Предупреждение `EventletDeprecationWarning` не мешает работе, но требует плана миграции.
- Аппаратное декодирование видео не реализовано (см. раздел о киоске).
- Второй экземпляр на другой плате установщиком ещё не проверялся.
