## Проект и документы

TeleRepka — информационная панель лаборатории на Repka Pi 4 с Flask/Socket.IO, Chromium kiosk на ТВ, WebRTC-трансляциями, управлением ТВ, фоторамками ESP32, датчиками и расписанием сотрудников.

## Рабочая система

- Основная плата: Repka Pi 4, Ubuntu 22.04 (по проверенной рабочей конфигурации).
- Репозиторий на плате: `/home/aaf/git/TeleRepka`; основная ветка `main`.
- Запуск: `/home/aaf/git/TeleRepka/.venv/bin/python /home/aaf/git/TeleRepka/app.py`.
- systemd: `lab-hub-kiosk.service` запускает Flask; Chromium запускается отдельно в GDM-сеансе.
- Flask: `http://127.0.0.1:5000/`; ТВ: `http://localhost:5000/?kiosk=1`; Chromium CDP: `127.0.0.1:9222`.
- Внешний адрес панели на рабочем месте: `https://telerepka-k207.istu.int/` (зависит от сетевого прокси, который установщик не создаёт).

## Обязательные правила

1. **Не запускать `deploy/install.sh` на основной работающей плате.** Он предназначен для чистой установки.
2. Не менять без отдельной задачи и проверки GDM, X11, GPU/Panfrost, параметры Chromium, 4K, масштаб 150%, HDMI-звук и автозапуск киоска.
3. Сохранять работу WebRTC, полноэкранного режима ТВ, Socket.IO, CDP Screencast и управления мышью/клавиатурой, фоторамок и расписаний.
4. Во время WebRTC-трансляции приоритет на ТВ остаётся у трансляции; экран расписаний не должен её вытеснять.
5. **Не коммитить** `data/laboratory_employees.db`, другие `data/*.db*`, ключи, сертификаты, пароли, резервные копии, временные файлы и журналы.
6. Не считать README доказательством работоспособности: проверять код, ответ сервиса и при необходимости результат на реальном ТВ.
7. Не удалять локальные незарегистрированные файлы пользователя (`backups/`, диагностические скрипты и т. п.) без разрешения.
8. Изменения — небольшими логическими порциями. Перед правками изучить связанные файлы и зависимости; после — проверить diff, синтаксис и поведение затронутых функций.
9. Разрабатывать новые функции в отдельных ветках, коммитить осмысленно, объединять с `main` после проверки. Не выполнять force-push и разрушительные Git-команды без явного согласования.
10. Если для проверки необходим перезапуск Flask, учитывать кратковременный разрыв WebSocket; не перезапускать GDM и не перезагружать всю плату без причины.

## Особенности

- `app.py` вызывает `employees.init_db()`: таблица SQLite создаётся автоматически; содержимое БД не распространяется через Git.
- `laboratory_sync.py` получает список сотрудников ИРНИТУ; `--apply` записывает изменения, но не назначает расписания автоматически.
- `sensors.py`: `read_dht11()` сейчас возвращает `None, None`; в коде есть чтение CO₂ через MH-Z19B на `/dev/ttyS2`. Не заявлять, что DHT11 работает, только на основании аппаратных комментариев.
- В проекте используется `eventlet`; его предупреждение об устаревании известно. Миграция требует отдельного тестирования.
- Изменение `templates/index.html` может потребовать перезапуска Flask и обновления браузера ТВ, чтобы отобразился новый шаблон.
