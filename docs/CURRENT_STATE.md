## Рабочие функции и границы подтверждения

- **Расписания сотрудников:** пользователь подтвердил работу зелёной кнопки, открытия справочника, перехода к расписанию, возврата к списку и синхронизации с ТВ. Код объединён с `main` через PR #2.
- **WebRTC и ТВ:** по предыдущим проверкам работают трансляция на ТВ, полноэкранный режим, возврат к панели, предпросмотр и удалённое управление. После будущих изменений проверять повторно.
- **Киоск:** Chromium в GDM-сеансе, CDP на loopback. Конфигурация 3840×2160 и масштаб панели 150% зафиксированы в документации; последний запуск `xrandr` по SSH не подтвердил фактический режим.
- **SQLite:** 20 сотрудников, но наличие расписания не гарантируется для каждого; ссылки на расписание и состав справочника — разные данные.
- **Датчики:** `sensors.py` явно отключает чтение DHT11, возвращая `None`; есть реализация MH-Z19B. Наличие текущих физических показаний последней диагностикой не подтверждалось.
- **Eventlet:** служба запускается, но в журнале присутствует `EventletDeprecationWarning`; это предупреждение, не ошибка запуска.
- **Фоторамки:** код опроса и прокси присутствует, но фактическая доступность каждой рамки в последней проверке не измерялась.

## Что не следует считать установленным фактом

- Разрешение и состояние HDMI на текущую минуту — требуется проверка в графической сессии.
- Аппаратное декодирование видео — не подтверждено.
- Корректность установки на второй Repka Pi — `deploy/install.sh` на второй плате ещё не тестировался.
- Состояние датчиков, Wi-Fi-клиентов и внешнего HTTPS после последней диагностики — проверять отдельно.
- Предупреждение Eventlet не означает аварии, но требует плана миграции при будущей модернизации.

## Важные ограничения

1. **Не запускать** `deploy/install.sh` на рабочей основной плате.
2. Не изменять GPU/GDM/X11/HDMI/масштаб без отдельной задачи.
3. Не заменять локальную SQLite-базу при обновлении Git; она не хранится в репозитории.
4. Обновление шаблона может потребовать перезапуска Flask и обновления Chromium/браузера.
5. Не использовать `xrandr` из SSH без корректного `DISPLAY` и `XAUTHORITY` как доказательство поломки ТВ.
